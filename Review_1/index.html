ENVIRONMENT & AGENTS — 3 / 3

Environment Characterization & Agent Architecture

Russell & Norvig's 7-dimensional environment taxonomy applied to urban emergency dispatch, followed by BDI agent internals and inter-agent coordination via FIPA-ACL.

🌐
7-Dimensional Environment Characterization
Mapping our problem space to Russell & Norvig's taxonomy
PARTIALLY OBSERVABLE
Observability
Ambulances see only their GPS cone + 500m. No agent has full city view. Dispatcher sees all AVL feeds but not patient conditions until paramedic reports.
STOCHASTIC
Determinism
911 arrivals follow Poisson(λ=4/hr). Traffic jams, patient deterioration, and hospital diversions are all probabilistic — requiring contingency plans.
SEQUENTIAL
Episodic vs Sequential
Dispatching AMB-101 to INC-A means it can't respond to INC-B. Each action constrains future fleet availability — the hallmark of sequential environments.
DYNAMIC
Static vs Dynamic
New emergencies arrive while ambulances are en-route. Traffic patterns shift. Hospital bed counts change between dispatch and arrival — the world doesn't wait.
CONTINUOUS
Discrete vs Continuous
GPS coordinates are continuous (lat/lng). Time flows continuously. We discretize the road network into a weighted graph for A* but the underlying state space is continuous.
COOPERATIVE
Multi-Agent
4 ambulances + 4 hospitals + 1 helicopter cooperate via FIPA-ACL protocols (CNP, Inform, Request). This is cooperative multi-agent, not competitive.
KNOWN STRUCTURE
Known vs Unknown
Road topology is known (OpenStreetMap), but edge weights (travel time) are dynamic. Hospital specialties are known, but bed availability is stochastic. This is a known structure with unknown parameters — justifying online replanning via D* Lite.
🧠
BDI Agent Architecture
Beliefs → Desires → Intentions → Plan → Execute → Monitor loop
01
Perceive
GPS fix, traffic feed, CAD alert — sensors update the belief base.
02
Deliberate
Desire generator ranks: "save life" > "minimize fuel" > "return to base".
03
Plan
A* computes shortest path. D* Lite patches if a road is jammed mid-route.
04
Commit
Agent locks intention: "Respond to INC-1042". Sends BID via CNP.
05
Execute
Path-following controller + siren activation. Monitors vitals en-route.

ALGORITHMS & SEARCH — 3 / 3

Algorithmic Modeling & Search Strategy

Three core algorithms power AURA-EMS: A* for initial pathfinding, D* Lite for real-time replanning under dynamic edge costs, and Gale-Shapley for stable ambulance-hospital matching.

🔎
Search Algorithms — A* & D* Lite
Optimal pathfinding under dynamic traffic conditions
INITIAL PLAN
A* Search
f(n) = g(n) + h(n)
g(n): cumulative cost from start (travel time considering speed limits & congestion).
h(n): Euclidean distance / max_speed — admissible & consistent heuristic.
Guarantee: returns optimal path when h is admissible. O(b^d) worst case, ~O(n log n) with priority queue.
REAL-TIME REPLAN
D* Lite (Incremental)
If edge(u,v) changes → update rhs(u) → reinsert to open list → propagate
Trigger: traffic jam detected on current route.
Advantage: only re-expands affected nodes, not entire graph. O(k log k) where k = changed nodes.
vs Full A*: 60-80% fewer node expansions on replans.
💍
Stable Matching — Gale-Shapley Algorithm
Ambulance ↔ Hospital matching with guaranteed stability (no blocking pairs)
AMBULANCE PREFERENCES
Proposer Side
Each ambulance ranks hospitals by: (1) specialty match (cardiac → cath lab), (2) travel distance, (3) historical offload delay. ESI-1 cardiac patients weight cath-lab availability 3× higher than distance.
HOSPITAL PREFERENCES
Responder Side
Each hospital ranks incoming ambulances by: (1) patient severity (ESI-1 first), (2) specialty alignment, (3) current bed load (prefer sending overflow elsewhere). Diversion threshold at 90% capacity.

A* adds an admissible heuristic h(n) that prunes branches of the search tree that can't improve on the current best path. In our road graph (~35 nodes), this reduces node expansions by ~40% vs Dijkstra, which is equivalent to A* with h=0. The heuristic (Euclidean distance / max_speed) is both admissible and consistent.
D* Lite activates when the ambulance is already en-route and a traffic change is detected on a future edge. It only re-expands the nodes affected by the cost change (O(k log k), k = changed nodes), while full A* would re-expand the entire graph (O(n log n)). For small changes (1-2 jammed edges), D* Lite is 60-80% faster.
Greedy "nearest hospital" can create unstable matchings: Ambulance A prefers Hospital 1 but gets Hospital 2, while Hospital 1 has capacity and would have preferred A's patient (blocking pair). Gale-Shapley guarantees no such blocking pair exists — the matching is stable, meaning no ambulance-hospital pair would mutually prefer to deviate.
1) Dispatcher broadcasts Call-For-Proposals (CFP) with incident details. 2) Available ambulances compute utility U(a,i) and submit BID messages. 3) Dispatcher selects highest-utility bidder and sends ACCEPT. 4) Other bidders receive REJECT. This is FIPA-ACL compliant and avoids centralized bottleneck — each agent independently computes its bid.
No single agent sees the complete state: (1) Ambulances don't know other ambulances' exact positions until AVL ping arrives (1 Hz latency). (2) Hospitals don't see incoming patients until pre-alert. (3) Dispatcher sees GPS feeds but not patient vitals until paramedic reports. (4) Traffic jams may exist on roads the ambulance hasn't traversed yet.
Our ambulance is a Utility-Based Agent with BDI architecture. It maximizes a multi-attribute utility function U(a,i) = −(γ·ETA + δ·Dist + ψ·load + ζ·fuel). It's not a simple reflex agent (no if-then rules), not model-based (it has a utility function, not just a world model), and not purely goal-based (it optimizes, not satisfices).
